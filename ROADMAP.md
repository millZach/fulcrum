# Fulcrum Roadmap

Every milestone deepens a working end-to-end product. A milestone cannot be completed by placeholder nodes or mocked production results.

## M0 — Real walking skeleton

Prove one real brief → creative revision → concept → approval → 3D asset → QA → Three.js scene lineage using one static hero prop. See [milestones/M0.md](milestones/M0.md).

## M1 — Creative-to-concept generalization

- Accept varied game briefs.
- Run Grill Me With Docs until the decision-tree frontier is empty and shared understanding is confirmed.
- Generate multiple purposeful visual directions.
- Support per-concept regeneration and partial direction changes.
- Expand the Visual Bible's structured visual tokens.
- Demonstrate that downstream prompts inherit approved direction without manual rewriting.

## M2 — Concept-to-3D quality

- Add Asset Planner output and dependency visualization.
- Support hero, kit, procedural, and functional classification.
- Add multiview concepts where provider capability warrants them.
- Expand deterministic mesh, material, texture, and topology checks.
- Add semantic turntable evaluation and evidence-backed findings.
- Support at least one strategy-changing regeneration path.

## M3 — Asset refinement

- Add Blender as a refinement adapter.
- Render repeatable turntables.
- Translate a bounded set of semantic findings into structured geometry and material operations.
- Re-evaluate and retain the best asset revision.
- Add conversion and rigging hooks without making Blender project truth.

## M4 — Three.js visual slice

- Generate a small modular environment kit.
- Expand Scene Spec to cover composition, procedural dressing, gameplay spacing, and interaction intent.
- Assemble a visually coherent arena from approved assets.
- Add controlled lighting, atmosphere, camera, and environment rendering.
- Suspend for high-leverage visual-slice approval.

## M5 — Visual refinement graph

- Classify visual issues before modification.
- Route asset, material, lighting, camera, composition, density, environment, and VFX findings correctly.
- Compare candidates against the best-known revision.
- Add budgeted improvement loops and oscillation detection.
- Demonstrate measurable improvement without hiding regressions in another dimension.

## M6 — Minimal gameplay

- Implement the movement, camera, interaction, combat, enemy behavior, objective, and UI required for a 5–10 minute slice.
- Add gameplay instrumentation and deterministic interaction tests.
- Connect gameplay constraints back into scene composition.
- Preserve the approved visual direction while implementing mechanics.
- Use human playtesting as the authoritative fun assessment.

## M7 — Gauntlet

- Add visual, gameplay, and technical evaluation streams.
- Introduce play-capable evaluation only when it can interact with and instrument the build.
- Prioritize findings by impact, confidence, cost, dependencies, and regression risk.
- Improve the highest-value issues under bounded budgets.
- Track best-known builds and restore them when a strategy regresses or oscillates.

## Later expansion

- Audio and advanced VFX production
- Additional image and 3D providers
- Godot adapter, followed by Unity and Unreal exploration
- Collaboration and remote artifact storage
- Larger game genres and longer playable slices
- Calibrated autonomous gameplay evaluation

Additional runtimes and providers are added through proven seams. They do not require changing the core project, provenance, approval, or Scene Spec semantics.
